## Commands

- `npx astro dev --background`: start the dev server in the background (localhost:4321). Manage it with `astro dev stop | status | logs`
- `npm run dev:contact`: run the contact form's dev endpoint alone (`astro dev` already starts it), restarting on changes
- `npm run build`: production build to `dist/`. Needs `PUBLIC_CONTACT_ENDPOINT` (see Forms), so locally keep a gitignored `.env.production` with `PUBLIC_CONTACT_ENDPOINT=http://localhost:8787/contact/`
- `npm run preview`: serve the built site
- `npm run build:lambda`: bundle the contact Lambda (`functions/contact/lambda.ts`) with esbuild into `.lambda/lambda.zip` (gitignored), leaving out the AWS SDK, which the runtime has
- `npm test`: run the Vitest suite once (`npm run test:watch` to watch). Tests live next to the code as `*.test.ts` (in `src/`, `functions/` and `infra/`) and render `.astro` components to HTML with Astro's container API (`astro/container`); `vitest.config.ts` uses `getViteConfig` so they get the Astro config.
- `npm run test:e2e`: Playwright browser tests in `e2e/` (desktop Chrome and a Pixel 7), run against a production build served on port 4322. They cover axe WCAG 2.2 AA checks in light and dark mode on every page in `src/pages` (nested ones too), every page of the blog list and the newest three posts and projects (each shares a template), that no page (every post and project included, as content can break a layout) scrolls either way (five desktop sizes from 1024×768 to 2560×1440, plus the phone), the mobile menu, the theme toggle, the skip link, the panel line animation (including reduced motion) and hover patterns. First run locally needs `npx playwright install chromium`. `.github/workflows/test.yml` runs both suites and the build on every PR and push to main, then on main deploys (see Hosting).
- `npx astro check`: type-check `.astro`/TS files. There's no linter yet. (`@astrojs/check` isn't installed, so the first run will prompt to add it.)

Requires Node >= 22.23.4 (Astro 7).

## Architecture

A personal portfolio site (`https://alexbaulderstone.com`), built as a static Astro 7 site with Tailwind CSS v4.

- **Layout chain**: pages → `src/layouts/Frame.astro` (a viewport-inset `.frame` box with a thick `.frame-border` overlay, styled in `global.css`. The frame is exactly one viewport tall (`height`, not `min-height`), and Frame's content wrapper is `min-h-0 overflow-y-auto`, so a page never scrolls: anything taller scrolls inside the frame. Content sits in a centred `max-w-5xl` column unless the page passes `panels`. The frame and that column are flex columns that fill the frame's height, so a page can centre content vertically by wrapping it in a `flex-1` element, as the home page does) → `src/layouts/Base.astro` (the HTML shell). Pages pass `title` and `description` props down through `Frame`. `Base` uses them for `<title>`, the meta description and a canonical URL built from `Astro.site`. `Base` also adds the skip link and the `<main id="main">` wrapper, so pages shouldn't add their own `<main>`. `Frame` renders `src/components/SiteNav.astro` into `Base`'s named `header` slot, outside `<main>`. The frame insets are CSS variables on `:root` in `global.css`, so the nav and the frame stay aligned. On mobile the bottom inset is taller to leave room for the fixed menu button.
- **Panels**: `<Frame panels>` drops the frame's padding and the `max-w-5xl` column so a page fills the frame edge to edge, then divides it with a `.panels` grid whose gaps are `--frame-width` wide (`min-h-0`, so it shrinks to fit the frame). Panels mark dividers with the `edge-b` (`::after`, in the gap below) and `edge-l` (`::before`, in the gap to the left) utilities, which draw a `--frame-color` line that meets the border and other lines. Lines draw in on load (`scaleX`/`scaleY`); stagger them with `--edge-delay` and set a horizontal line's start with `--edge-origin` (default `left`). Both work with breakpoint variants (`max-md:edge-b md:edge-l`). Don't put `overflow` on a panel with an edge, as it clips the line: scroll an inner wrapper instead (see the about page's Bio region), and give it `scroll-shadow` (`global.css`) so it reads as scrollable where scrollbars are hidden (iOS Safari). Each page defines its own grid, so the frame stays put and the inside rearranges. `src/pages/about.astro` is the reference.
- **Career page**: `src/pages/career.astro` reads the `career` content collection (`src/content.config.ts`: one Markdown file per company in `src/content/career/`, all in frontmatter: `company`, `stack`, and `roles` newest first, each with `title`, `start`, an optional `end` (left out while current), an optional `summary` and `highlights`). The timeline shows one entry per company, spanning its roles, newest first. The URL hash is the state, with no JS: each job's article has the job's id (`/career/#coder-academy`), timeline entries are links to it, everything per job is rendered hidden, and an inline `<style>` generated per job shows the set whose article is the `:target` (the newest job when there's no matching hash). On mobile the timeline runs across, oldest on the left, with arrow links to the earlier and later jobs. On mobile a stack that won't fit one row (estimated at build time from its length by `src/lib/marquee.ts`, which has no Astro imports so the e2e tests pick a long and a short stack with it) scrolls as a `marquee` (`global.css`: the list twice in a track, the copy `aria-hidden`), with a checkbox pause button for WCAG 2.2.2; under reduced motion it wraps instead.
- **Blog**: posts are the `blog` collection (`src/content.config.ts`: one Markdown file per post in `src/content/blog/`, its file name being the slug, with `title`, `description`, `pubDate`, optional `updatedDate`, `tags` and `draft`; drafts show in dev only). `src/lib/blog.ts` has `getPosts()` (newest first), `readingTime` and `formatDate`; `src/lib/blog-config.ts` (no Astro imports, so the e2e tests can read it) sets `POSTS_PER_PAGE` and `RSS_POSTS`. `/blog/` (`src/pages/blog/[...page].astro`) lists the posts a page at a time (`/blog/2/` and so on, with a bar of older / newer arrows and numbered page links once there's more than one page; `src/lib/pagination.ts` works out which numbers to show); `/blog/<slug>/` (`[slug].astro`) shows one, with its tags and a link back to all posts in a left column on md+, and an older / All posts / newer bar on mobile (where the tags sit in the post's header). Post pages use `edges-static` (`global.css`) so the lines don't redraw on every click. Post text uses `prose prose-site` (the typography plugin in the site's colours), and code blocks are Shiki with light and dark themes (`astro.config.mjs`: `github-light` and `github-dark-default`, as `github-dark`'s comments fail 4.5:1) that follow the theme toggle. Markdown goes through Astro 7's default processor, Sätteri, which takes its own hast plugins (`satteri({ hastPlugins })`), not `rehypePlugins`; `src/lib/task-list-labels.ts` gives task-list checkboxes (`- [ ]`) an `aria-label` from their item's text. SEO: `Base` takes optional `type`, `publishedTime` and `modifiedTime` for Open Graph, and has a `head` slot (forwarded by `Frame`) that posts use for `BlogPosting` JSON-LD. `src/pages/rss.xml.ts` is the RSS feed (the newest `RSS_POSTS`), linked from every page's `<head>`.
- **Projects**: the `projects` collection (`src/content.config.ts`: one Markdown file per project in `src/content/projects/`, its file name being the slug, with `title`, `description`, `date` (shown as the year, and sets the order), `stack`, its GitHub `repo` (required) and deployed `url` (optional: no Live site link without one), and `draft`). `src/lib/projects.ts` has `getProjects()` (newest first). `/projects/` (`src/pages/projects/index.astro`) shows every project as a card (no pagination), one column on phones and a grid from md, with the title link stretched over the card. `/projects/<slug>/` (`[slug].astro`) mirrors a blog post, with a Links panel (GitHub and live site, with icons) and the stack in place of the tags; on mobile both sit in the post's header.
- **Forms**: `src/components/form/`: `FormField` (a label plus an input or textarea, with any validation attributes passed through), `SubmitButton` and `ContactForm` (used by `src/pages/contact.astro`: name, email, an optional mobile number and message, one field per line at every size). Validation is the browser's, with no client JS: each field's error message sits below it, `invisible` until the field is `:user-invalid` (Tailwind's `peer-user-invalid:`), so its line is always reserved. `fieldClass` adds classes to the control (the contact form shortens the textarea on `short:` screens). The form fits its panel without scrolling from 1920×1080 up (checked in `e2e/contact.spec.ts`); on laptop screens it scrolls inside the panel. `ContactForm` takes an optional `error` for the whole form (a `role="alert"` line below the fields, beside the button) plus `action` and `method` (default `post`). The form is a plain POST (still no client JS) to `PUBLIC_CONTACT_ENDPOINT`, an `astro:env` variable (`astro.config.mjs`) that's required, so a build without it fails. The endpoint answers with a 303 to `src/pages/contact/thanks.astro` or `src/pages/contact/error.astro` (both `noindex` and left out of the sitemap). The form's rules (`MESSAGE_MIN_LENGTH`, `MOBILE_PATTERN`, `MAX_LENGTHS`) live in `src/lib/enquiry.ts`, which the endpoint checks too (`parseEnquiry`), plus a hidden `website` honeypot field that marks a submission as spam. The endpoint lives in `functions/contact/`: `handler.ts` handles a submission whatever receives it, given an `EnquiryStore` and a `Mailer` (it stores the enquiry, emails the sender and the owner, and redirects). `dev-server.ts` is a zero-dependency `node:http` server on 8787 that Node runs directly (type stripping, so imports there need `.ts` extensions and only erasable TypeScript), with `dev-deps.ts` storing enquiries in `.dev-data/enquiries.json` and writing emails to `.dev-data/outbox/` (gitignored); `GET /contact/` lists what's stored. `integration.ts` starts it with `astro dev` and stops it with `astro dev stop`. `.env.development` and `.env.test` (for Vitest) point the form at it; the e2e tests run their own on 8788 (`playwright.config.ts`) and check the enquiry was stored. In production `lambda.ts` wraps the same `handleContact` behind a Lambda function URL, storing enquiries in DynamoDB and sending through SES (`dynamoStore`, `sesMailer`), and `PUBLIC_CONTACT_ENDPOINT` is the function URL (see Hosting). The owner's notification sets `replyTo` to the sender; the sender's acknowledgement deliberately doesn't repeat their message, so the form can't be used to deliver text to a stranger's address. Colours: labels `nebula-700` / `phosphor-300` in the body font, borders a lighter step of the frame colour (`nebula-500` / `phosphor-600`, 3:1), darker borders plus a frame-coloured ring on focus, inputs on `paper-50` / `void-900` with `paper-600` / `void-400` placeholders, and ember when invalid.
- **Hosting**: AWS, defined in Terraform in `infra/` (run from a laptop, state in the `alexbaulderstone-tfstate` bucket; set `owner_email` in a gitignored `infra/terraform.tfvars`). A private S3 bucket behind CloudFront (Origin Access Control, cert in us-east-1, the existing Route 53 zone read with a `data` source so Terraform never manages it). `infra/functions/rewrite.js` is a CloudFront Function that adds `index.html` to directory paths (a private S3 origin only does that at the root), adds missing trailing slashes and redirects www; it's tested in `rewrite.test.ts`. Missing paths get `src/pages/404.astro` (`/404.html`). The contact Lambda, its DynamoDB table and SES (DKIM, a `bounce.` MAIL FROM, DMARC) are in `contact.tf` and `ses.tf`; Terraform creates the function with a stand-in and ignores code changes, as deploys upload the real code. `scripts/deploy.sh` uploads `dist/` (hashed `_astro/` assets cached for a year, the rest cached at the edge until the invalidation it then makes) and `.lambda/lambda.zip`; the workflow's deploy job runs it through an OIDC role (`infra/github.tf`, trusted only by the repo's `production` environment), reading repository variables `AWS_DEPLOY_ROLE_ARN`, `SITE_BUCKET`, `DISTRIBUTION_ID`, `CONTACT_FUNCTION` and `CONTACT_ENDPOINT`, and is skipped until they're set.
- **Social links**: `src/lib/socials.ts` (no Astro imports, so the e2e tests read it) lists the GitHub, LinkedIn and Instagram URLs. `src/components/SocialLinks.astro` renders them as icon and label, or as icons alone with `compact` (each link named with `aria-label`). The contact page shows them in a left "Elsewhere" panel on md+ and as an icon bar along the bottom of the frame on mobile.
- **Patterns**: `pattern-dots`, `pattern-grid`, `pattern-hatch`, `pattern-crosshatch`, `pattern-stripes` and `pattern-checker` (in `global.css`) are faint background patterns in a tint of `--frame-color`, so they follow the theme. Add `pattern-on-hover` to reveal one only on hover or keyboard focus. Tune with `--pattern-strength` (default 14%; keep it low for text contrast) and `--pattern-color`. Light mode multiplies the strength by `--pattern-boost` (1.25), because patterns read fainter on paper. The fade uses a registered `@property --pattern-alpha`. Tailwind only emits the ones a page uses. They're backgrounds, not pseudo-elements, so they combine with `edge-b` / `edge-l`.
- **Starfield**: `src/components/Starfield.astro` is a decorative, pure-CSS background (used on the landing page) that fills the frame inside the border. It has four layers of square pixel stars, each a seeded SVG tile used as a mask over `--frame-color`. They drift at different speeds for parallax, the two plus-shaped layers twinkle out of step, and they hold still under reduced motion. Content after it needs `relative` to paint above it. Strength per theme is `--starfield-strength` (0.9 light, 1 dark).
- **Icons**: one component per icon in `src/components/icons/` (`HomeIcon`, `MapPinIcon`, ...), each wrapping the shared `Icon.astro` base: a 24px grid, 2.5 stroke in `currentColor`, `aria-hidden`, `size-7` unless you pass `class` (which replaces it). Draw new icons in the same style rather than adding an icon library; `icons.test.ts` picks up any new `*Icon.astro` automatically.
- **Mobile nav**: the drawer uses the Popover API (`popover` / `popovertarget`) with CSS `@starting-style` transitions, so it needs no client JS.
- **Styling**: Tailwind v4 is set up through the Vite plugin, not `@astrojs/tailwind`, and there is no `tailwind.config.js`. All theme config lives in CSS in `src/styles/global.css` (`@theme` tokens such as `--color-brand`, `--font-sans` and `--font-heading`, plus `@plugin "@tailwindcss/typography"`). `Base.astro` is the only place that imports it. The `dark:` variant is redefined with `@custom-variant` in `global.css`: it follows `prefers-color-scheme` unless `<html data-theme="light|dark">` overrides it. `src/components/ThemeToggle.astro` (rendered by `Frame` in a `<footer>` that fills `Base`'s named `footer` slot after `<main>` and sits in the frame's bottom inset; the button starts `hidden` and its script reveals it, so it never appears without JS) sets that attribute and saves it to localStorage, and an inline script in `Base`'s `<head>` reapplies it before paint.
- **Fonts**: loaded with Astro's built-in Fonts API (`fonts` in `astro.config.mjs`, which self-hosts them from Google at build time and generates metric-matched fallbacks). `Base` renders a `<Font>` for each. Roboto is the body font (`--font-sans`); Press Start 2P is the heading font (`--font-heading`, applied to `h1`–`h6` in `global.css`). Press Start 2P is drawn on an 8px grid, so keep it at multiples of 8px (16, 24, 32px) to stay crisp. Each glyph is exactly 1ch wide, so `max-w-[Nch]` controls where it wraps.
- **Responsive type and breakpoints** (in `@theme` / `global.css`): `--text-fluid` (`lg:text-fluid`) is body text that scales from 18px at 1024px to 26px at ~2560px. Cap long text at about `max-w-[70ch]`. `3xl` (1920px) is for stepping Press Start 2P up a size on very wide screens. `short:` (viewports under 896px tall, a `@custom-variant`) is for tightening padding and row sizes so a page still fits one screen on short laptops.
- **Routing/SEO**: `trailingSlash: 'always'` is set in `astro.config.mjs`, so internal links need trailing slashes (`/about/`, not `/about`). `@astrojs/sitemap` generates the sitemap from `site`.

## Rules

- trailingSlash: 'always'; every page uses the Frame layout
- Accessibility: semantic HTML, visible focus, 4.5:1 text contrast, honour prefers-reduced-motion. A region that scrolls needs `tabindex="0"`, a role and a label so keyboard users can scroll it
- Every page fits one viewport with no page scroll (checked by `e2e/layout.spec.ts`); use `short:` to tighten layouts on short screens
- SEO: every page needs title, description, canonical URL
- Don't animate main content opacity (hurts LCP); animate the border only
- Zero client JS unless there's a clear reason
- Light mode accent: icons (menu, theme toggle etc.), links and headings are nebula (`nebula-600`), phosphor in dark mode; body text is grey: `paper-800` in light mode, `void-200` in dark mode
- Code will be pushed to feature branches named feature/{description}
  - Merges will happen on github, but prompt me if there are unmerged changes before switching to another branch
